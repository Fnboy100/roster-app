feat(frontend): add Floor roster UI — image-style table, validation panel, coverage-rule editor

Integrates the new backend Floor scheduling engine into the existing
roster page rather than forking a parallel one — RosterApp.jsx branches
on department code, so every other department's generate/submit/
approve/change-request flow is byte-for-byte unchanged.

- api/rosterEngine.js — new API module: shift-template and coverage-
  rule CRUD, ensure-default-catalog, generate (returns
  { period, validation }), submit-for-approval, per-cell override, and
  get-validation-report. Mirrors the existing api/roster.js/auth.js
  module pattern (one thin function per endpoint, JSDoc comment naming
  the route and payload shape).

- components/roster/FloorRosterTable.jsx — the image-style table: role
  groups with a colored band header, one cell per day showing the
  shift code (background color from the shift template) + its hours,
  Total Hours and Balance columns (balance computed against that
  role's coverage-rule target_weekly_hours), and a "Working today" row
  per group for a quick per-day headcount. When the period is a draft,
  clicking a cell turns it into a shift-code picker that calls
  onOverride(entryId, shiftCode) — editing only reachable pre-approval,
  matching the backend's draft-only override endpoint.

- components/roster/ValidationPanel.jsx — renders the six validation
  categories (missing coverage, consecutive-shift violations,
  split-eligibility issues, manual-override conflicts, over/under
  target hours) as collapsed-when-empty sections, or a single "all
  clear" line when there's nothing to show.

- components/roster/FloorSettingsPanel.jsx — inline (not a separate
  route) shift-catalog summary and a per-role coverage-rule editor:
  min staff/day, off days/week, target/max weekly hours, max
  consecutive-closing streak, split-allowed and senior-rotation
  checkboxes, with a Save button per row that only enables once that
  row's form actually differs from the loaded rule.

- pages/RosterApp.jsx — the integration point:
  - isEngine = isEngineDepartment(currentDepartmentCode) gates every
    branch below; false for every department except Floor.
  - load() additionally fetches shift templates + coverage rules, and
    the validation report for whatever period is loaded; isDraft is
    now derived from the backend's period.status === 'draft' for
    engine departments (previously always a local-only flag).
  - handleGenerate/handleSubmit branch to the engine API for Floor,
    unchanged client-side path otherwise.
  - new handleOverrideEntry(entryId, shiftCode) for draft-only manual
    edits, reloading both the period and the validation report
    afterward so the panel never shows stale results.
  - render swaps in FloorRosterTable + ValidationPanel (and
    FloorSettingsPanel behind a "Shift & Coverage Rules" toggle,
    replacing the old client-only Rules panel) for engine departments;
    CSV/PDF export keep working unchanged since `roster` state is
    still populated from the same entries via the existing
    entriesToRoster mapper.

- data/constants.js — DEPARTMENT_POSITIONS.FLOOR extended with Butler,
  Cashier, CRM Officer, Hostess (from the reference roster image) with
  matching POSITION_COLORS entries; new
  ENGINE_DEPARTMENT_CODES/isEngineDepartment() used by RosterApp.jsx —
  the single switch that would need a department code added to extend
  this to another department later.

No new routes were added — everything renders inline on the existing
/roster page, so there's nothing new to wire into App.jsx or Layout.jsx.
